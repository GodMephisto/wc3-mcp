# 0.5.46 - 2026-11-26

- The imaging dependency is SkiaSharp 3.119.4, MIT, in place of ImageSharp 3.1.12. Every release of ImageSharp from 3.2.0 up carries the Six Labors Split License and refuses a Release build without a key, so the pinned version could never move and its six open advisories could never be answered by upgrading. SkiaSharp has no licence gate, and a Release build now needs no key.
- `SafeImages` sniffs the magic numbers itself and refuses anything not PNG, JPEG, BMP, GIF or TGA before a decoder exists. ImageSharp could be told to ignore metadata, SkiaSharp cannot and its codec parses whatever container it is handed, so the buffer decides the format now, not the library. PNG ancillary chunks and JPEG APP1 to APP15 and COM segments are stripped before the decoder sees them, so no ICC profile, EXIF block or comment reaches it.
- TGA output is written and read by our own uncompressed and RLE 24 and 32-bit codec, because SkiaSharp has no TGA encoder. `.tga` still round-trips without loss, alpha included, and a TGA that is not true-colour 24 or 32-bit is refused rather than half-decoded.
- Grayscale heightmaps keep an exact 16-bit PNG path of their own, since a general codec routes 16 bits through an 8-bit or half-float intermediate and a height would move by up to half a world unit. The round trip is sample for sample exact.
- `.bmp` is still written as 24-bit, which is what the old encoder produced, so map assets converted to BMP keep the same bytes and a reader still sees alpha as 255. `.gif` is still palette-quantised and decodes to its first frame.
- Every rasterizer keeps its own depth buffer and per-pixel loop, so the blending arithmetic and its rounding are untouched. Where a public signature carried the old pixel type it now carries the Skia one, `Rgba32` to `SKColor` and `Image<Rgba32>` to `SKBitmap`, and `TerrainRenderer.ColorForTerrainType` returns the three channel bytes instead of a pixel struct.
- A decode that asks for more than 67 megapixels is refused before any pixel is allocated, and a truncated file decodes as far as its rows go rather than failing, both as before.
- Build warnings fall from 62 to 38, the difference being obsolete ImageSharp API warnings that no longer exist.

Requirement, none. Defect, GHSA-v76p-62qx-wwq2, GHSA-j9gm-c75j-xc9q, GHSA-wmxv-xphr-5c9g, GHSA-jjfr-hcj7-qf5w, GHSA-gwg2-r3hj-4w44, GHSA-j3p4-wp97-rph4. Those six become unreachable rather than contained, because the library they live in is gone.
